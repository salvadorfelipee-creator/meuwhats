# Compliance, LGPD e riscos de mídia paga

Use antes de publicar em saúde, jurídico, seguros/finanças, emprego, habitação, educação, suplementos, álcool ou qualquer campanha com dados pessoais e depoimentos. Esta referência é operacional, não parecer jurídico; revise a política vigente da plataforma, normas do setor e orientação profissional quando necessário.

## 1. Matriz de risco

| Risco | Exemplo | Prevenção | Dono/prazo/critério |
| --- | --- | --- | --- |
| Promessa absoluta | “garantimos resultado” | linguagem condicional, prova e limite | responsável da oferta, antes da aprovação; zero claims não comprovados |
| Atributo pessoal | “Você está endividado?” | falar da situação sem inferir identidade | copy, antes de subir; revisão de política aprovada |
| Saúde/estética | medo, cura, antes/depois irregular | benefício informativo, consentimento e revisão | profissional responsável, D-1; aprovação documentada |
| Jurídico | promessa de ganho de causa | explicar processo, riscos e limites | advogado responsável, D-1 |
| Discriminação | excluir/segmentar atributo sensível | critérios legítimos e revisão | mídia, D-1 |
| Habitação/emprego/crédito | segmentação ou copy excludente | checar categoria e regras da plataforma | mídia + jurídico, D-2 |
| Depoimento | foto/frase sem autorização | termo, contexto, data e edição fiel | cliente/operação, D-3 |
| LGPD | capturar e-mail/telefone sem finalidade | minimização, base legal, acesso, retenção e opt-out | controlador, antes da coleta |
| WhatsApp | mensagem fria/disparo | opt-in, identificação, saída e cadência | atendimento, antes do fluxo |

## 2. Checklist de dados

1. Defina finalidade específica do dado e evento que ela atende.
2. Colete o mínimo; não peça dado sensível para qualificar mídia sem necessidade demonstrada.
3. Registre base legal, origem, data, texto do consentimento e preferência de canal quando aplicável.
4. Implemente opt-out simples e honre-o em todas as ferramentas.
5. Restrinja acesso por função; não compartilhe planilha aberta com dados pessoais.
6. Defina retenção e descarte; revise fornecedores e integrações.
7. Não envie PII crua em URL, UTM, evento ou criativo.
8. Documente incidentes, exclusões e auditorias.

## 3. Revisão de peça e página

| Pergunta | Sim/Não | Evidência |
| --- | --- | --- |
| A promessa é honesta, verificável e sem garantia? | | |
| A prova tem autorização e contexto? | | |
| O texto evita atributo pessoal e discriminação? | | |
| O preço, condição, prazo e limitações são claros? | | |
| Página e anúncio não induzem erro ou omitem custo relevante? | | |
| Consentimento e política de privacidade estão acessíveis? | | |
| Há opt-out no canal conversacional? | | |
| A categoria regulada foi revisada na política da plataforma? | | |

**Critério:** se qualquer resposta crítica for “não” ou “incerta”, não publicar; atribua responsável e data de correção.

## 4. Plano de resposta a reprovação ou incidente

1. Pause a peça/fluxo sem apagar evidências.
2. Registre motivo, ID da campanha, data, texto e impacto.
3. Corrija causa; não replique o mesmo anúncio com pequena alteração para contornar política.
4. Confirme com responsável do negócio/jurídico quando a categoria exigir.
5. Refaça teste de tracking, consentimento e opt-out.
6. Publique uma versão revisada só após aprovação.
7. Registre aprendizado no backlog.
